# The lightweight BASE needed to run the test suite, and nothing else.
#
# WHY THIS FILE EXISTS
# --------------------
# The test dependencies used to be one line (`pytest>=8.0`) inside
# requirements.txt — the file every END USER installs via start.bat. Two problems,
# and the second one cost a release:
#
#   1. Every install shipped a test runner it never runs.
#   2. "What CI installs" and "what a contributor has" were never stated, so they
#      drifted. pytest-flask lands on plenty of dev machines as a transitive dep;
#      CI installed requirements.txt and nothing else, so it did not have it. That
#      plugin wraps every test taking the `app` fixture in an autouse request
#      context, which makes a test that forgot `with app.app_context():` pass
#      locally and fail only in CI. Nine tests went out green and came back red on
#      the release tag.
#
# So: this file is the common lightweight test baseline. CI and release both
# install it (asserted by test_dev_requirements_contract), and it pins rather than
# floats — a suite that passes on a different pytest than CI's is not evidence
# about CI. The separately declared Torch overlay below completes runtime coverage.
#
#   python -m pip install -r backend/requirements-dev.txt
#   python -m pytest backend/tests -q
#
# Torch is intentionally a separate, pinned CPU-only overlay:
#
#   python -m pip install --no-cache-dir -r backend/requirements-torch-tests.txt
#
# Runtime tests for exact-state resume and the ai-toolkit bridge skip when that
# overlay is absent. CI installs it only when exact-state/bridge-sensitive paths
# change; release validation always installs it.
#
# NOTE on plugins: the suite runs with `-p no:flask` (backend/pytest.ini). Having
# pytest-flask installed anyway is harmless — it is disabled, deliberately, so a
# machine that carries it behaves exactly like one that does not. Do NOT add it
# here to "match" a dev machine; matching is what pytest.ini already guarantees.

# The app itself — the tests import it.
-r requirements.txt

# Pinned, not floated: CI and a contributor must run the SAME collector.
pytest==9.1.1

# The suite is ~7150 tests whose cost is FLAT: measured 2026-08-08, the ten
# slowest tests are 7.5% of the time and the 5286-test tail is 74% of it, at
# ~243 ms each. There is no hotspot to fix -- more than half of that time is
# fixture setup, i.e. the per-test `create_app` that every one of conftest's
# isolation comments exists to justify. Making that fixture cheaper would mean
# sharing an app between tests, which is exactly the leak those comments were
# written after. So the suite is made parallel instead: a worker is a process,
# so every module-global, env var and :memory: DB stays as isolated as it is
# today, and the wall clock drops from ~30 min to ~2.5 min on a 32-core box.
#
# Run it with:  python -m pytest backend/tests -q -n 8 --dist loadfile
#
# `--dist loadfile` (not the default `load`) keeps every test of one FILE on one
# worker. Several files build state across their tests, and per-test scattering
# is a different execution order, not just a faster one.
#
# A fixed worker count, not `-n auto`: a few tests assert on ELAPSED TIME rather
# than on a result (test_bank_scan_no_db_lock gives a concurrent writer a 400 ms
# budget), so saturating every core on a big machine makes them report on the
# load instead of on the code. CI pins 4; 8 is the local default.
pytest-xdist==3.8.0

# The backend's lint gate (`ruff check .` from the repo root, rules in ruff.toml).
# Pinned exactly for the same reason pytest is: CI's lint job reads THIS pin and a
# run on a different ruff is not evidence about CI. Correctness-class rules only —
# unused imports and variables, undefined names, duplicate dict keys, bare
# excepts, mutable defaults — never style, so a green check means something.
ruff==0.16.4

# Torch's official CPU index otherwise resolves an old vulnerable setuptools.
# Install the audited build backend from PyPI in the base environment first so
# the optional overlay reuses it instead of downgrading through that index.
setuptools==84.0.0

# Test-only ML extras. These are never in requirements.txt on purpose: the app
# installs them into dedicated environments on demand (see requirements-ml.txt).
# A handful of suites — test_watermarks.py above all — exercise real numpy/OpenCV
# pixel maths and the Telea fallback that runs when LaMa is absent, so these
# (and ONLY these in the lightweight base: Torch has its own overlay, while
# LaMa stays absent) make those tests run for real while keeping "LaMa absent"
# true.
numpy>=1.26,<2
opencv-python-headless>=4.9

# safetensors belongs HERE and not in the Torch overlay: that overlay carries
# `--index-url .../whl/cpu`, so anything added to it resolves from PyTorch's
# index instead of PyPI — the exact substitution the pinned setuptools above
# exists to prevent. Its own contract test pins it to the Torch wheel alone.
#
# test_zimage_convert_streaming.py guards on Torch (`importorskip`) but reads
# and writes real .safetensors containers, so on a machine that HAS Torch the
# guard passes and the import still fails. That machine is CI: the dev box
# carries safetensors transitively and stayed green, so the divergence only
# surfaced on the release tag — the second time this file's own header describes
# that exact failure, now on a different package. Declared, so the streaming
# converter is actually exercised in release validation rather than skipped.
safetensors>=0.4

# instaloader belongs here for the SAME reason safetensors does, and this is the
# THIRD time this file's header describes the same shape. test_instagram_scan.py
# imports it at module level — everything in that file is mocked, no network is
# ever touched, but the module is needed for the `instaloader.Profile`/`Post`
# namespace the fakes stand in for. It ships in requirements-scrape.txt, an
# OPTIONAL extra the app installs on demand, so a contributor who ran the scraper
# once has it transitively and stays green while CI, which installs this file and
# nothing else, cannot even collect the module. That is a collection ERROR, not a
# skip: it failed the release tag, not a test.
#
# Declared rather than guarded with `importorskip` on purpose. A skip would turn
# the suite green by removing the only place the Instagram verdicts are pinned —
# and those verdicts are the point: an empty profile is an empty RESULT, while a
# post that refuses to parse stays a real failure. Pure Python, no wheels to
# build, so running it for real costs nothing.
instaloader>=4.12
